# 2026-10-10 工作记录

## 系统性 403 根因定位 + 前置检查机制落地

### 现象
用户报告 2026-10-10 起下载**全部** 403（含换新 ttwid 重试 3 次仍失败），与之前"偶发 403 重试即成功"不同。用户假设"第三方库有更新但本地没更新"。

### 根因（证据链）
- **「依赖过期」假设不成立**：`uv pip install --dry-run "f2>0.0.1.7"` → `only f2<=0.0.1.7 is available` → **f2 0.0.1.7 即 PyPI 最新版，无更新可升**。
- **非本机 IP 单封**：在完全不同 IP/网络 的干净环境实测同一 `aweme/detail` 接口，同样 403（带 f2 a_bogus 签名）→ 全局服务端校验变更。
- **真正根因**：抖音服务端更新了对匿名 `a_bogus` 签名的校验，f2 0.0.1.7 内置的 2024 开源 a_bogus 算法（`f2/utils/abogus.py`，`@version 0.0.2`）已被服务端拒绝 → 匿名接口系统性失效。
- **纠正旧误判**：`gen_false_msToken()` 每次调用均返回**随机**串（`gen_random_str(126)+"=="`），并非常量。"日志里 3 次 msToken 相同"实为 f2 `BaseRequestModel.msToken` **导入期生成的类属性**（只生成一次），不是本工具 cookie 里的 msToken，非根因。

### 落地改动（src/douyindl/downloader.py + logger.py + config/config.yaml + docs）
1. **依赖自检 `_check_deps_fresh`**：启动查 PyPI f2 最新版，有更新则 `uv pip install` 升级并 `os.execv` 重启加载新版（实现"下载前先更新依赖库"；当前无新版时为 no-op）。
2. **连通性探针（金丝雀）`_canary_probe`**：批量下载前用 `_CANARY_AWEME_IDS`（3 个公开视频）各探测一次；只要任一"接口可达"（含视频已删/私密）即放行；仅当全部 403/风控 才判"方法整体失效"，打印 `_report_method_blocked()` 诊断并 `sys.exit(2)` 中止，避免整批误写 `urls_fail`。
3. **真实登录态 Cookie 绕过 `login_cookie`**（config.yaml 新增）：非空则 `build_cookie()` 直接返回，跳过匿名生成 → 当前唯一可靠"一劳永逸"绕过手段（需含 sid_tt/sess 等，有过期时间）。
4. **压制 f2 控制台噪音**：`setup_logger` 内 `logging.getLogger("f2").setLevel(logging.CRITICAL)`，屏蔽 f2 标准 logging 的 403 长串噪音（含"请前往QA文档"）。
5. 新配置项：`login_cookie` / `preflight_check_deps` / `preflight_canary`（均默认空/true）。`preflight_canary:false` 可强制跳过探针走原流程。

### 验证
- 冒烟测试：新字段加载正确；金丝雀在当前被拦截环境正确返回 False（3 候选全 BLOCKED）；登录 cookie 短路生效。
- 全流程 CLI：依赖自检跳过（已最新）→ 金丝雀判失效 → 打印 3 行诊断并退出。
- f2 日志压制后控制台无 403 刷屏；`--help` 与两文件编译均 OK。

### 结论
匿名下载器在抖音持续改服务端的前提下无法"一劳永逸"；本次把"快速暴露失效 + 自动跟进 f2 升级 + 登录 Cookie 绕过"做成真实机制。文档已同步 CLAUDE.md（403 节新增"系统性 403"小节）与 docs/02-config.md。
