# 2026-10-10 工作记录

## 系统性 403 根因定位 + 前置检查机制落地

### 现象
用户报告 2026-10-10 起下载**全部** 403（含换新 ttwid 重试 3 次仍失败），与之前"偶发 403 重试即成功"不同。用户假设"第三方库有更新但本地没更新"。

### 根因（证据链）
- **「依赖过期」假设不成立**：`uv pip install --dry-run "f2>0.0.1.7"` → `only f2<=0.0.1.7 is available` → **f2 0.0.1.7 即 PyPI 最新版，无更新可升**。
- **非本机 IP 单封**：在完全不同 IP/网络 的干净环境实测同一 `aweme/detail` 接口，同样 403（带 f2 a_bogus 签名）→ 全局服务端校验变更。
- **真正根因**：抖音服务端更新了对匿名 `a_bogus` 签名的校验，f2 0.0.1.7 内置的 2024 开源 a_bogus 算法（`f2/utils/abogus.py`，`@version 0.0.2`）已被服务端拒绝 → 匿名接口系统性失效。
- **纠正旧误判**：`gen_false_msToken()` 每次调用均返回**随机**串（`gen_random_str(126)+"=="`），并非常量。"日志里 3 次 msToken 相同"实为 f2 `BaseRequestModel.msToken` **导入期生成的类属性**（只生成一次），不是本工具 cookie 里的 msToken，非根因。

### 落地改动（src/douyindl/downloader.py + logger.py + config/config.yaml + docs）
1. **依赖自检 `_check_deps_fresh`**：启动查 PyPI f2 最新版，有更新则 `uv pip install` 升级并 `os.execv` 重启加载新版（实现"下载前先更新依赖库"；当前无新版时为 no-op）。
2. **连通性探针（金丝雀）`_canary_probe`**：批量下载前用 `_CANARY_AWEME_IDS`（3 个公开视频）各探测一次；只要任一"接口可达"（含视频已删/私密）即放行；仅当全部 403/风控 才判"方法整体失效"，打印 `_report_method_blocked()` 诊断并 `sys.exit(2)` 中止，避免整批误写 `urls_fail`。
3. **真实登录态 Cookie 绕过 `login_cookie`**（config.yaml 新增）：非空则 `build_cookie()` 直接返回，跳过匿名生成 → 当前唯一可靠"一劳永逸"绕过手段（需含 sid_tt/sess 等，有过期时间）。
4. **压制 f2 控制台噪音**：`setup_logger` 内 `logging.getLogger("f2").setLevel(logging.CRITICAL)`，屏蔽 f2 标准 logging 的 403 长串噪音（含"请前往QA文档"）。
5. 新配置项：`login_cookie` / `preflight_check_deps` / `preflight_canary`（均默认空/true）。`preflight_canary:false` 可强制跳过探针走原流程。

### 验证
- 冒烟测试：新字段加载正确；金丝雀在当前被拦截环境正确返回 False（3 候选全 BLOCKED）；登录 cookie 短路生效。
- 全流程 CLI：依赖自检跳过（已最新）→ 金丝雀判失效 → 打印 3 行诊断并退出。
- f2 日志压制后控制台无 403 刷屏；`--help` 与两文件编译均 OK。

### 结论
匿名下载器在抖音持续改服务端的前提下无法"一劳永逸"；本次把"快速暴露失效 + 自动跟进 f2 升级 + 登录 Cookie 绕过"做成真实机制。文档已同步 CLAUDE.md（403 节新增"系统性 403"小节）与 docs/02-config.md。

## v0.7.0：修复「MSE 视频解析不到直链」误报（同日续）

### 现象
`--resolve browser` 下部分视频报 `页面已加载但未取到视频直链…可能触发了验证码或视频已删除`，
但**页面标题/文案已正常取到**（即页面加载正常、视频存在），且第三方 App「即存」能正常下载。

### 根因（实测定位，非推测）
抖音 PC Web 播放器对**部分**视频启用 **MSE**（Media Source Extensions）：
- `<video>.currentSrc` 是 `blob:https://www.douyin.com/...`，**不是 http 直链**；
- 真实地址在网络层，且被拆成**两条独立流**（MP4 box 实测）：
  - `.../media-video-avc1/` → 仅画面 `['vide']`
  - `.../media-audio-und-mp4a/` → 仅声音 `['soun']`
- v0.6.0 兜底 JS 用 `.mp4/.m4s/.m3u8` 扩展名正则过滤性能记录，而抖音 VOD 地址形如
  `.../media-video-avc1/?a=6383&br=551...`，**路径里没有扩展名** → 连兜底也一并落空。

故障样本 `7680879925243711922` 实测：`<video>` 的 `readyState=4`、`duration=855s`、
`paused=false`、`error=null`（**播放完全正常**），却一个 url 都没匹配到。
→ 结论：**是代码问题，不是视频被删/触发验证码**（原报错文案本身是误导）。

### 修法
改用**拦截页面自己发出的 `aweme/detail` 响应体**（`_DetailSniffer`）：
不自己实现签名，让真实浏览器把带签名请求发出去，再截响应体解析，
拿到与 f2 接口**同构**的完整 JSON。其中 `video.bit_rate[]`/`play_addr` 是
**渐进式合流** MP4（实测 moov 内同时含 vide+soun），正是需要的地址。

### 改动文件
- `browser_fallback.py`：新增 `_DetailSniffer` / `_pick_best_muxed_url` / `_aweme_to_resolved`；
  `BrowserResolved` 增 `cover_url`/`music_play_url`/`raw_aweme`；重写 `_CDPSession`；
  修 `_collect_mix_ids` 收敛判据。
- `downloader.py`：`_from_browser_resolved` 复用 `_extract_video_meta`，
  按 `music_play_url` 决定 `music_status`（不再硬置 0）。
- `CLAUDE.md`：新增 v0.7.0 节 + 变更记录，修正「浏览器路径拿不到元数据」的旧表述。

### 踩坑（已修，勿回退）
1. **CDP 必须单读循环**：响应与事件同走一条 socket，原 `call()` 里 recv 到匹配 id 就丢事件 → 无法监听。改为唯一读循环 + Future 分发。
2. **读循环里不得 await 需要 CDP 回包的命令**（如 `getResponseBody`）→ 读循环自己挂起、收不到自己的回包 → **死锁**（表现为静默超时）。必须 `create_task` 派发。
3. **`Network.enable` 必须开大缓冲**，否则数百 KB 的 detail 响应体被回收、取不到。
4. **`_collect_mix_ids` 收敛判据**：不能在「从未采到 id」时触发（加载期 DOM 为空会误报"未列出任何视频"）；
   但**也不能**用 `document.readyState === "complete"` 作守卫——`/collection/{id}` 会 302 到第一个视频页，
   `complete` 时侧栏已被**推荐流**灌满，会采到**与合集无关的视频**（实测取到高考/ChatGPT/幼儿园）。
   正确做法：只要求「采到过 id 后才允许收敛」。

### 验证
- 故障视频端到端下载成功：114,282,084 字节，与服务端 `Content-Range` 总长**完全一致**；
  box 实测 `['soun','vide']` 合流；末尾字节非全 0。
- 6 条视频批量解析 6/6，单条约 4~6 秒（不必等播放器起播，比 v0.6.0 的「等 5 秒起播」更快）。
- 合集 3/3 正确（合集本身而非推荐流）。
- `-m all` 产出 **5 种文件齐全**（.mp4/.jpg/.mp3/.json/.txt）——v0.6.0 时浏览器路径只有 .mp4/.txt/.json。
- 原始故障命令 `uv run python -m douyindl -i urls` 复跑：3/3 成功。
