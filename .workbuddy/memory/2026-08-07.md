# 2026-08-07

## 修复：抖音分享短链批量下载偶发 403 失败

- **根因**：抖音对 `aweme/detail`、合集列表接口有间歇性风控（偶发 403 Forbidden）。
  f2 的 `base_crawler.handle_http_status_error` 对 403/429/5xx 走 `else` 分支**直接抛
  `APIResponseError`、不进入重试循环**（只在响应为空时重试），日志里 `尝试次数：1` 即证据。
  所以批量下载时零星分享链接直接失败；用户发现换 PC 链接（换新会话重跑）反而能成功。
- **修复**（src/douyindl/downloader.py）：
  - 新增 `_request_with_retry(fetch_factory, config, label)`：包裹 `fetch_one_video` /
    `fetch_mix_videos` 的接口调用；每次重试 `build_cookie()` 重新生成匿名 ttwid（换新会话），
    退避用 `_random_interval(max(api_request_interval, 2.0))`；仅重试
    `APIResponseError/APIRateLimitError/APIConnectionError/APITimeoutError`，逻辑错误不重试。
  - 配套 `_make_mix_call` / `_make_post_detail_call` 协程工厂（每次返回全新协程）。
  - 新增 `config.api_max_retries`（默认 3），已写入 config.yaml + Config + docs/02-config.md。
- **验证**：真实请求第一次 403 → 重试换新会话第二次成功；端到端用
  `https://v.douyin.com/97Vj07kqups/`（aweme_id 7666021943149071616）整链路跑通。
- **提交**：`6d3cd37` fix: 修复抖音分享短链偶发403风控导致的下载失败（4 文件，已排除 urls 用户数据）。
- **说明**：分享链接与 PC 链接在代码里本来就走同一个 `fetch_one_video`，问题不在
  "share vs PC" 两种路径，而是 f2 不重试 403。故无需为分享链接单独走 PC 页面解析。
