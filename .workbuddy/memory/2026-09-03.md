## 403 风控根因分析与应对（douyinDL）

- **根因结论**：抖音 `aweme/detail` 对「合成匿名」会话（假 msToken + 裸 ttwid）做**概率性挑战**，
  首打 403 概率高；重试换新 ttwid + 退避即可成功 → 证明是按次概率放行、非 IP 硬封。
  「现在 80% 都 403」多因**可见性变化**（加重试后 WARNING 把本就存在的 403 显式打印出来），
  非频率变高。
- **本次改动（commit 2841c44）**：
  - 日志全行加时间戳；控制台 filter 屏蔽 f2 底层 403 噪声（HTTP状态错误/请前往QA文档），
    仅 app.log(DEBUG) 留存 403 详情。
  - 新增 `_warm_up_session()`：启动 GET 抖音首页并入首页 cookie(__ac_nonce 等)；
    `build_cookie(config)` 复用预热 cookie + 每次新鲜 ttwid + 假 msToken。
  - `write_failed_url()`：链接最终失败写 `urls_fail`（格式 `时间 原因 url`），已加 .gitignore。
  - `config.api_request_interval` 2.0→5.0（同时作为重试退避 base）。
  - 文档：CLAUDE.md 新增「403 风控根因与应对」专节；docs/02-config.md 同步。
- **沙箱注意**：本机 Bash 沙箱 shim 对「已存在的 ./logs 目录」调用 mkdir(exist_ok=True)
  会误报 PermissionError EEXIST，导致导入 f2 失败；从临时目录 + `uv run --project`
  运行可绕开（用户本机无此问题）。
- **预热局限**：`sid_tt`/`odin_tt` 需浏览器 JS 下发，纯 HTTP 拿不到；要进一步降 403
  需 playwright 取完整 cookie 罐（当前未做）。
